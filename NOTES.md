## Шаг 2 — хуки (29.09.2026)

- **Один вход** `hooks/scripts/dispatch.mjs <Event>` на пять событий: `SessionStart`, `UserPromptExpansion`, `PreToolUse` (все инструменты: §9 требует журналировать каждый вызов), `PostToolUse` (запись файлов), `SubagentStop`. Только Node, без зависимостей; контракт берётся из `lib/crew-contract.mjs`. Цена: ~20 мс на вызов инструмента вне crew-сессий и ~33 мс внутри.
- **Отличия от PLAN.md:**
  - команда в shell-форме (`node "${CLAUDE_PLUGIN_ROOT}/…"`), а не exec-форма — проверена на живом CLI;
  - метка сессии — `.crew/sessions/<id>.json`, как в контракте (шаг 1);
  - `WebFetch` не ограничен allowlist'ом: §9 требует этого только для `curl`/`wget`, а агентам нужна документация. Вызовы `WebFetch` журналируются.
- **Только в crew-сессиях** (решение 6). `/agent-crew:new-project` и `/agent-crew:feature` через `UserPromptExpansion` пишут метку `.crew/sessions/<session_id>.json` и `.crew/.gitignore` (`logs/`, `sessions/`). Хост (eval-раннер) вместо метки задаёт `CREW_HOST`. В остальных сессиях хук выходит сразу и ничего не пишет. `/status` сессию не помечает: он только читает.
- **Политика** — `hooks/policy.core.json` плюс `skills/stacks/<профиль>/policy.json` поверх. Там защищённые ветки, разрешённые хосты, пороги для пакетов и их allowlist, зоны записи по ролям, безопасные команды и цены.
- **Три исхода `PreToolUse`:**
  - `deny` с причиной для агента («Blocked by the agent-crew policy: …»);
  - `allow` — для записи в своей зоне и для цепочек из безопасных команд;
  - без ответа — решает хост по режиму прав пользователя.
- **Что запрещено (§9):**
  - `rm`/`find -delete` вне проекта, всего проекта или с целью, которую нельзя вычислить заранее;
  - запись вне проекта: редиректы, `cp`/`mv`/`install`/`ln`/`tee`/`touch`/`mkdir`/`truncate`/`dd of=`/`sed -i`;
  - `git push` в main/master, force-push (`-f`, `--force-with-lease`, `+refspec`), `--all`/`--mirror`;
  - `curl`/`wget` на хосты не из списка;
  - установка и запуск через npx/dlx пакетов не из allowlist, которые не прошли проверку реестра (существует, старше 30 дней, от 1000 скачиваний в неделю); git-, URL-, file-спецификации, свои реестры и глобальные установки;
  - настоящие секреты в `.env*` (шаблоны `.env.example` и локальные значения docker compose разрешены) и любая запись в `.env` через shell;
  - запись вне зоны роли.
- **Как разбирается shell:** разбор best-effort. Он раскрывает `sudo`, `env`, `sh -c`, `eval`, `xargs`, `find -exec` и `$(…)`, отслеживает `cd`. Переменные и подстановки считаются неизвестными: для опасных команд это запрет, для остальных — просто без автоодобрения. Скрипт из `sh -c "…$X…"` проверяется по именам команд, но автоодобрения не получает никогда.
- **Проверка реестра:** кэш в `${CLAUDE_PLUGIN_DATA}/registry-cache.json` (успех — сутки, отказ — час). Сетевые ошибки дают отказ и не кэшируются.
- **`PostToolUse`:**
  - файл в `.crew/`, нарушающий контракт, возвращает `decision: block` со списком ошибок и подсказкой про `crew` CLI;
  - правки кода пишутся в `.crew/logs/edits.jsonl` как хэши «до/после» (для поиска метаний на шаге 3).
- **`SubagentStop`** добавляет в `.crew/costs.log` оценку (`source: estimate`) по транскрипту сабагента. Токены считаются без повторов по id сообщения, задача берётся из первого сообщения, цены — таблица на 25.09.2026.
- **Журнал** `.crew/logs/hooks.jsonl` хранит решение, инструмент, агента и хэш входа, но не сам ввод.
- **Роли:** `agent-crew:<роль>` получает зону роли. Главный поток и чужие агенты (`general-purpose`, `other-plugin:frontend`) получают зону оркестратора: `.crew/**` и `docs/**`. Задачи и эскалации могут писать все.
- **Проверки:**
  - 62 теста `node:test` (`plugins/agent-crew/hooks/test`): разбор shell, все сценарии §9 и попытки обхода, зоны, секреты, реестр с поддельным `fetch`, кэш, и `dispatch.mjs` отдельным процессом, как его запускает Claude Code. Покрытие строк 98%.
  - `claude plugin validate --strict` проходит.
  - На настоящем CLI 2.1.283 без обращения к модели (без входа, `total_cost_usd: 0`): `hooks.json` загружен, `UserPromptExpansion` записал метку и `.gitignore`, `additionalContext` принят.
  - В CI добавлен job `hooks` (ubuntu и macos).
- **Открыто:**
  - **Codex (шаг C):** Codex не передаёт `agent_type`, поэтому зоны по ролям там не работают — все агенты получат зону оркестратора и не смогут писать код. Нужен другой признак роли (например, переменная окружения агента) или отключение зон в Codex.
  - **Сеть:** `ssh`/`scp`/`rsync`/`nc` и сеть из `node -e`/`python -c` хук не запрещает, их решает хост.
  - **Живая проверка `PreToolUse`** нужна на шаге 6: для неё требуется вызов модели.

## Шаг 3 — агенты, скилы `core/`, CLI `crew` (30.09.2026)

- **9 агентов** в `plugins/agent-crew/agents/` (оркестратор — главный поток, решение 5.1).
  - Модели по §5: critic, architect и security на `opus`, keeper на `haiku`, остальные на `sonnet`. У всех задан `effort`, `maxTurns` и минимальный список `tools`, без `Agent`: делегирует только оркестратор.
  - Разделы по SPEC («Цель», «Зона ответственности», «Запрещено», «Входы», «Выходы», «Критерий готовности», «Кому эскалирует») идут по-русски, а текст промптов — по-английски: кириллица стоит в 1,5–2 раза больше токенов, а этот текст грузится в каждый вызов агента. Всё, что видит пользователь (бриф, вопросы, отчёт), агенты пишут на языке проекта (`language` в `crew.json`).
  - У агентов с `WebFetch`/`WebSearch` есть оговорка «данные, а не инструкции» (§9).
- **Скилы `core/`** (все с `user-invocable: false`):
  - `crew-files`, `interview`, `brief`, `git-process`, `acceptance-tests`, `code-review`, `security-review`;
  - `orchestration` — сценарий главного потока по фазам §7;
  - `stuck-detection` — триггеры и лестница §8.
  - Агенты подгружают скилы через `skills:` по короткому имени. Проверено по коду CLI 2.1.283: имя ищется точно, затем как `<плагин>:<имя>`, затем по суффиксу.
- **CLI `crew`** (`bin/crew` → `cli/*.mjs`, без зависимостей, контракт из `lib/`):
  - **Задачи.** `task new|list|show|start|submit|pass|reject|fail|block|set` и `next`. CLI сам ведёт цикл задачи (§7.7) и лестницу (§8): 3 неудачи на ступени или повтор ошибки поднимают задачу `retry → stronger_model (opus) → replan`, дальше эскалация. Хэш ошибки не зависит от чисел и путей во временных папках. Вывод `fail`/`reject` заканчивается строкой «Next:» — оркестратор выполняет её буквально.
  - **Эскалации и решения.** `escalate` блокирует задачу. `escalation answer|resolve|cancel`: `resolve` требует ADR и снимает блокировку задачи. `decision new` умеет помечать заменённое ADR.
  - **Проект.** `init`, `config`, `status show|set`, `check`, `budget`, `summary`, `validate`, `interview pending|answer`, `id next`.
  - **`crew check`** проверяет потолок бюджета (по отчёту хоста, иначе по оценке), долю бюджета задачи, взаимные откаты правок (по `logs/edits.jsonl`) и эскалации, на которые пора ответить.
  - Id выделяются эксклюзивно; запись атомарная; перед созданием файла данные проверяются схемой, поэтому пустых файлов после ошибки не остаётся.
- **Контракт** (версия остаётся 1, добавлены только необязательные поля): `ladder` у задачи, `language` в `crew.json`, папка `.crew/reviews/`. Написан `crew-contract/README.md` (PLAN §2.5).
- **Хуки:**
  - команды переведены в exec-форму (`command: node`, `args`), как рекомендуют документация и PLAN;
  - `SubagentStart` передаёт каждому агенту плагина контекст: стек и скил `<стек>-stack`, язык проекта, автономию, правила `.crew/`, оговорку про веб-контент;
  - метка сессии хранит снимок конфига: переменные `CLAUDE_PLUGIN_OPTION_*` могут не доходить до Bash, а CLI должен видеть тот же потолок бюджета;
  - `SubagentStop` обновляет `spent_usd_estimate` задачи;
  - **роли `crew`-команд** (`crewCommands` в политике): `task pass|reject --stage X` может запустить только агент X, `task set`, `init`, `escalation answer|resolve` — только оркестратор, `decision new` — архитектор и оркестратор, `status set` — хранитель и оркестратор;
  - **поля задач и эскалаций** нельзя менять через Write/Edit: хук сравнивает frontmatter до и после, текст ниже frontmatter править можно; новые файлы создаёт только CLI;
  - **git в общей рабочей копии:** всем запрещены `stash`, `reset --hard`, `clean`, `restore`, `checkout` файлов, `commit --amend` и `--no-verify`, `rebase`. Переключать ветки и делать `git add -A` / `commit -a` может только оркестратор. `git stash`, `checkout`, `merge` и `restore` убраны из списка безопасных команд, добавлен `npm audit`;
  - у QA в зоне теперь `docs/ui-contract.md` и `.crew/reviews/`, у security — `.crew/reviews/`.
- **Проверки:**
  - тесты плагина: хуки — 70, CLI — 24, проверка файлов агентов и скилов — 70 (всего 164); тесты контракта — 92;
  - `claude plugin validate --strict` проходит;
  - на живом CLI 2.1.283 без входа ($0): загружены 9 агентов `agent-crew:*` и 9 скилов `core`;
  - `bin/crew` виден в `PATH` инструмента Bash: пробный скил с `!`-подстановкой выполняет `command -v crew` и `crew help` до обращения к модели;
  - exec-хуки срабатывают, метка содержит конфиг.
- **Решения:**
  - параллельная работа — несколько вызовов Agent в одном сообщении с `run_in_background: false`. Так результат доходит и в `-p`, и в интерактивной сессии. В фоне работает только хранитель;
  - главный поток сам не пишет код и бриф: хук ограничивает его зоной `.crew/**` и `docs/**`.
- **Открыто:**
  - **Стековый скил `tanstack-stack`,** на который ссылаются агенты и контекст `SubagentStart`, появится на шаге 4.
  - **Поведение агентов с моделью** (соблюдают ли они цикл и лестницу) проверим на шаге 6.
  - **claude.ai и Cowork** не ставят плагины с `bin/` в корне. Нам это не мешает: целевая платформа — Claude Code.
